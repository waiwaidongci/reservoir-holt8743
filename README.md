# 雨水回用池液位趋势预测

根据晨检液位估算未来几天的水位和高位预警日期。

澄湾会展园物业水务班组，4 名值班员轮班管理园区冲洗供水和 RW-02 雨水回用池。 值班员每天 07:00 从液位计抄取 RW-02 读数，换表或通讯中断时，台账会留空一天。班长导入单池日读数，比较带趋势和仅水平的预测，核对留出期误差后，把预警日期与预测表交给负责巡检和回用排班的机电组。

- 园区冲洗用水和进水变化会改变水位走势，沿用昨日读数容易推迟高位巡检。
- 断报前后的读数在表格里紧挨着，容易被当成相邻两天。
- 仅看拟合曲线，交班时很难判断预测提前几天仍然可用。

## 演示流程

1. 11 月 20 日 07:00，补录 RW-02 的 1.91 m 晨检读数。
2. 在「晨检液位台账」导入「澄湾_RW-02_20261101-20.csv」，确认 11 月 4 日缺报。
3. 在「池位预测设置」设置未来 6 天、末尾留出 4 天和 2.05 m 高位预警线。
4. 在「水位预报与评估」查看两模型在同一组滚动起点的单步误差，以及随后 4 天的留出误差。
5. 查看逐日预报，默认参数预计 11 月 23 日首次触线。结合当班回用计划安排液位计巡查。
6. 在「高位巡检复核」登记值班决定，从「机电交班报告」下载预测表。

## 计算口径

- 按日历日期排序。一个批次只能有一座池，每天一条晨检读数。遇到缺报时同时重置两个模型，取截止日所属的连续段；报告列出缺测区间。
- Holt 用前两日初始化水平 L₂=y₂、趋势 B₂=y₂−y₁。其后更新 Lₜ=αyₜ+(1−α)(Lₜ₋₁+Bₜ₋₁)，Bₜ=β(Lₜ−Lₜ₋₁)+(1−β)Bₜ₋₁。提前 h 天预报为 Lₜ+hBₜ。
- 仅水平模型从 S₁=y₁ 开始，用 Sₜ=αyₜ+(1−α)Sₜ₋₁ 更新，所有提前量的预测均为 Sₜ。两模型的负预测统一按 0 m 计。
- 末尾连续留出指定天数。更早的数据用前三日作为初始训练，逐日先预测再纳入实测，至少比较两次单步误差。按滚动 MAE 选模型，同分优先仅水平；两套留出预测都以留出前一天为固定起点。
- 评估后，两模型用整段连续实测重算未来逐日点预测。选中模型首次预测达到或超过警戒线时记为触线；末日实测已达线时直接报告实测日期。预测比较允许 10⁻¹² m 的浮点误差。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | PostgreSQL 16 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
